# Security Specification — FC Online PC Simulator

## 1. Data Invariants
1. **Zero PII Storage**: Neither `/users/{userId}`, `/users/{userId}/cards/{cardId}`, `/cloud_managed_accounts/{accountId}`, `/cloud_managed_accounts/{accountId}/cards/{cardId}`, `/leaderboard_entries/{userId}`, `/server_config/{configId}`, `/server_broadcasts/{broadcastId}`, nor `/admins/{adminId}` may store emails, password hashes, phone numbers, IP addresses, or physical addresses.
2. **Strict Ownership, Verified Writes & Tiered GM Admin RBAC**: Every Firestore write (`create`, `update`, `delete`) requires `request.auth != null` and `request.auth.token.email_verified == true`.
   - **Tier 1 (GM Admin — `isAdmin()`)**: Verified bootstrapped GM email (`daipss9789@gmail.com`) or UID present in `/admins/{uid}`. May manage `/server_config/global_rules`, `/server_broadcasts/{broadcastId}`, `/cloud_managed_accounts/{accountId}` (+ `/cards/{cardId}`), `/leaderboard_entries/{userId}`, and target `/users/{userId}` (+ `/cards/{cardId}`) while strictly preserving `isValid[Entity]` schema constraints and identity invariants. Only the root bootstrapped GM email (`isBootstrappedAdminEmail()`) may `create` or `delete` `/admins/{adminId}` for delegated Google UIDs.
   - **Tier 2 (Standard Verified Player — `userId == request.auth.uid`)**: May only create/update their own `/users/{userId}`, `/users/{userId}/cards/{cardId}`, and `/leaderboard_entries/{userId}` when not banned (`!isBanned`), and is strictly forbidden from self-granting `isDelegatedAdmin`, self-unbanning `isBanned`, or forging `adminRevision`.
3. **Master Gate Relational Sync**: `/users/{userId}/cards/{cardId}` verifies parent `/users/{userId}` exists (or `existsAfter` in batch) with `ownerId == userId`; `/cloud_managed_accounts/{accountId}/cards/{cardId}` verifies parent `/cloud_managed_accounts/{accountId}` exists (or `existsAfter` in batch) with `accountId`; `/leaderboard_entries/{userId}` verifies parent `/users/{userId}` (or `/cloud_managed_accounts/{userId}` when written by `isAdmin()`) exists.
4. **Immutable Identity, Legacy Doc Self-Heal & Temporal Integrity**: `ownerId`, `accountId`, `templateId`, `boardScope`, `syncScope`, and `configId` cannot be altered on `update` (if a pre-schema legacy `/users/{userId}` document lacked `ownerId` or `createdAt`, it must initialize strictly to `userId` and `request.time`, after which both remain immutable); `/server_broadcasts/{broadcastId}` and `/admins/{adminId}` forbid `update` entirely; `createdAt` (on create) and `updatedAt` (on create/update) must strictly equal `request.time`.
5. **Bounded Collections, Maps, Numeric Ranges & Strings**: `packs` map keys are strictly allowlisted (`iprm_pack`, `le_pack`, `ucl_26`, `vb_26`, `icon_tm`, `toty_26`, `tots_26`, `bdo_pack`, `up_pack`, `ucl_25`, `cu_fodder`), `elo` (`1000..10000`), `wins`/`draws`/`losses` (`0..1000000`), `managerXp` (`0..100000000`), `managerLevel` (`1..100`), `squadOvr` (`0..300`), `bestCardOvr` (`0..300`), `foosballLoops` (`0..1000000`), `claimedBroadcastIds` (`size() <= 50`), `claimedMilestones` (`size() <= 24`), `claimedVipRewards` (`size() <= 24`), and every string field enforces explicit `.size()` limits.
6. **Enforced List Boundaries (Zero DB Reads in `list`)**: `/users/{userId}`, `/server_config/{configId}`, and `/admins/{adminId}` forbid `list` entirely; `/users/{userId}/cards/{cardId}` enforces `resource.data.ownerId == request.auth.uid` (or `isBootstrappedAdminEmail() && resource.data.ownerId == userId`); `/cloud_managed_accounts/{accountId}` restricts `list` strictly to `isBootstrappedAdminEmail() && resource.data.syncScope == 'GLOBAL'`; `/cloud_managed_accounts/{accountId}/cards/{cardId}` enforces `resource.data.accountId == accountId && resource.data.syncScope == 'GLOBAL'`; `/leaderboard_entries/{userId}` enforces `resource.data.boardScope == 'GLOBAL'`; `/server_broadcasts/{broadcastId}` enforces `resource.data.scope == 'GLOBAL'` — all with zero `get()`/`exists()` inside `list`.

## 2. The "Dirty Dozen" Adversarial Payloads
1. **Unverified Admin Email Spoof**: Authenticated user with `email: 'daipss9789@gmail.com'` but `email_verified: false` writes `/server_config/global_rules`, `/cloud_managed_accounts/local_test`, or `/users/{otherUid}` -> `PERMISSION_DENIED`.
2. **Non-Admin Server Rules / Cross-Web Account Tampering**: Verified regular player attempts to toggle `guaranteedUpgrade100: true` in `/server_config/global_rules` or write `/cloud_managed_accounts/local_victim` -> `PERMISSION_DENIED` (`isAdmin()` gate).
3. **Self-Assigned Admin Escalation**: Authenticated regular user creates `/admins/{uid}` or sets `isDelegatedAdmin: true` on `/users/{uid}` -> `PERMISSION_DENIED`.
4. **Cross-Tenant Private Read by Non-Admin**: Non-admin user `uid_B` calls `get` on `/users/uid_A` -> `PERMISSION_DENIED`.
5. **Private User Enumeration (`list`)**: Regular user calls `list` on `/users`, `/server_config`, or `/cloud_managed_accounts` -> `PERMISSION_DENIED`.
6. **Shadow / Ghost Field Injection**: User or Admin updates `/users/{uid}`, `/cloud_managed_accounts/{id}`, or `/leaderboard_entries/{uid}` adding `isAdmin: true` -> `PERMISSION_DENIED` (`hasOnly` + `affectedKeys().hasOnly` rejection).
7. **Value / Resource Poisoning**: User creates `/leaderboard_entries/{uid}` with `elo: 999999` or a 5,000-char `managerName` -> `PERMISSION_DENIED` (`1000 <= elo <= 10000`, `size() <= 32`).
8. **ID Poisoning**: User creates `/users/uid_A/cards/invalid$id!@#` or `/server_config/other_doc` -> `PERMISSION_DENIED` (`isValidId` regex + `configId == 'global_rules'`).
9. **Orphaned Subcollection Card**: User creates `/users/uid_A/cards/card_1` before `/users/uid_A` exists, or Admin creates `/cloud_managed_accounts/local_x/cards/c1` before parent `/cloud_managed_accounts/local_x` exists -> `PERMISSION_DENIED` (Master Gate parent check).
10. **Timestamp Forgery**: User submits `updatedAt` or `createdAt` 1 hour in the future instead of `serverTimestamp()` -> `PERMISSION_DENIED` (`request.time` check).
11. **Immutable Broadcast / Identity Mutation**: Admin attempts to `update` an already-published `/server_broadcasts/{id}` or mutate `ownerId` / `accountId` -> `PERMISSION_DENIED`.
12. **Banned User Self-Unban / VIP Out-of-Range Escalation**: Banned user attempts to write `isBanned: false` on `/users/{uid}`, or payload writes `vipLevel: 99` / negative `fc: -500` -> `PERMISSION_DENIED`.
